# وكيل الطباعة — دليل التركيب على جهاز المطعم

الموقع مستضاف على الإنترنت، وما عنده طابعة. هذا الوكيل هو الجسر بينه وبين
الطابعة الحرارية: يسأل الموقع كل ثوانٍ "أكو فاتورة جديدة؟"، يطبعها، ويبلّغ الموقع
أنها طُبعت.

**انسخ مجلد `agent` كامل إلى جهاز Windows في المطعم** — الجهاز اللي الطابعة
موصولة بيه. ما تحتاج تنسخ أي شي ثاني من المشروع.

مثال لمكان مناسب: `C:\pizza-print`

> هذا دليل **تركيب وتشغيل**. لشرح الآلية نفسها — كيف يُبنى الوصل، ولماذا وصلان،
> وماذا يحدث عند الأعطال — انظر [`PRINTING.ar.md`](../PRINTING.ar.md) في جذر
> المشروع.

---

## ١) تثبيت Node.js

نزّل نسخة **LTS** من <https://nodejs.org> وثبّتها (Next → Next → Finish).
لازم تكون **20 أو أحدث**.

للتأكد، افتح موجّه الأوامر (CMD) واكتب:

```
node --version
```

> ما تحتاج `npm install` — الوكيل بدون أي اعتماديات.

---

## ٢) المفتاح السري

هذا المفتاح هو اللي يثبت للموقع أن الوكيل هو الوكيل. **نفس القيمة** تنحط
بمكانين: على الموقع، وبملف إعدادات الوكيل.

على الموقع (Vercel ← Settings ← Environment Variables) أضف:

| المتغيّر | القيمة |
|---|---|
| `PRINT_AGENT_TOKEN` | سر عشوائي طويل |

تولّد واحد بأي جهاز فيه Node:

```
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

بعد إضافته **أعد النشر (Redeploy)** — Vercel ما يقرأ المتغيّر الجديد إلا بالنشر
التالي.

> ما دام هذا المتغيّر فارغ أو غير موجود، الموقع يردّ **404** على
> `/api/print/queue` و `/api/print/ack`، وما تنطبع ولا فاتورة. هذا مقصود: مفتاح
> غير مضبوط يجب ألّا يعني "ادخل بلا مفتاح".

---

## ٣) ملف `config.json`

انسخ `config.example.json` وسمّ النسخة **`config.json`** بنفس المجلد، وافتحها
بـ Notepad واملأها:

```json
{
  "siteUrl": "https://pizza-inky-two.vercel.app",
  "token": "نفس قيمة PRINT_AGENT_TOKEN بالضبط",
  "printerName": "",
  "pollMs": 3000
}
```

| الحقل | الشرح |
|---|---|
| `siteUrl` | رابط الموقع، **بدون `/` بالنهاية** |
| `token` | نفس `PRINT_AGENT_TOKEN` حرفاً بحرف |
| `printerName` | اتركه `""` ليستخدم الطابعة الافتراضية في Windows. لتثبيت طابعة بعينها، اكتب اسمها بالضبط كما يظهر في **الإعدادات ← الطابعات والماسحات** |
| `pollMs` | كل كم ميلي ثانية يسأل عن فاتورة جديدة |

`config.json` يحمل المفتاح السري، فيبقى على هذا الجهاز ولا يُرفع مع المشروع.

## ٤) التشغيل

اضغط ضغطتين على **`start-print-agent.bat`**. تنفتح نافذة وتبقى مفتوحة:

```
[8/24/2026, 7:04:11 PM] Print agent started.
[8/24/2026, 7:04:11 PM]   site:    https://pizza-inky-two.vercel.app
[8/24/2026, 7:04:11 PM]   printer: Windows default
[8/24/2026, 7:04:11 PM]   polling: every 3000 ms
[8/24/2026, 7:04:26 PM] 1 receipt(s) waiting.
[8/24/2026, 7:04:28 PM] ✓ PDN-4831 printed on XP-80C
```

**لا تغلق هذه النافذة** — إغلاقها يوقف الطباعة.

> هذه طريقة التجربة والمتابعة المباشرة. للتشغيل اليومي استخدم القسم ٦ (تشغيل
> تلقائي مخفي).

## ٥) اختبار بدون استهلاك ورق

أضف `testOutputFile` إلى `config.json`، فتُرسم الفواتير إلى ملف بدل الطابعة —
نفس الكود ونفس التنسيق، وما يخرج ورق:

```json
{
  "siteUrl": "https://pizza-inky-two.vercel.app",
  "token": "...",
  "printerName": "",
  "pollMs": 3000,
  "testOutputFile": "C:\\Users\\Public\\receipt-test.bin"
}
```

شغّل الوكيل، واضغط **طباعة الوصل** على أي طلب من لوحة التحكم، وراقب ظهور
`✓ … printed on …`. ظهور ملف بذلك المسار يعني أن السلسلة كاملة تعمل: الموقع،
والمفتاح، والفاتورة، ومشغّل الطابعة.

**بعدها احذف سطر `testOutputFile`** وأعد تشغيل الوكيل. ما دام موجوداً، يكتب
الوكيل `TEST MODE` عند الإقلاع ولا يخرج ورق أبداً.

## ٦) التشغيل التلقائي المخفي (الوضع اليومي)

حتى لا يضطر أحد لتذكّر تشغيله، وحتى لا تبقى نافذة سوداء على شاشة المطعم يغلقها
أحدهم بالخطأ.

نفّذ هذا **مرة واحدة** في PowerShell على جهاز المطعم — بدّل المسار إن كان المجلد
في مكان آخر:

```powershell
$agent   = "C:\pizza-print"
$action  = New-ScheduledTaskAction -Execute "wscript.exe" -Argument "`"$agent\start-hidden.vbs`"" -WorkingDirectory $agent
$trigger = New-ScheduledTaskTrigger -AtLogOn -User $env:USERNAME
$settings = New-ScheduledTaskSettingsSet -AllowStartIfOnBatteries -DontStopIfGoingOnBatteries `
              -StartWhenAvailable -RestartCount 3 -RestartInterval (New-TimeSpan -Minutes 1) `
              -ExecutionTimeLimit ([TimeSpan]::Zero)
$principal = New-ScheduledTaskPrincipal -UserId "$env:USERDOMAIN\$env:USERNAME" -LogonType Interactive -RunLevel Limited

Register-ScheduledTask -TaskName "PizzaPrintAgent" -Action $action -Trigger $trigger `
  -Settings $settings -Principal $principal -Force
```

من الآن فصاعداً: يبدأ الوكيل مع تشغيل الجهاز، بلا نافذة، ويعيد تشغيل نفسه إن
انهار.

> **لماذا "عند تسجيل الدخول" وليس "عند إقلاع الجهاز"؟** الطابعة مثبّتة لحساب
> مستخدم، ومهمة تعمل قبل دخول أي مستخدم لا تراها أصلاً. أجهزة المطاعم عادةً
> تدخل إلى حساب واحد تلقائياً، فالنتيجة واحدة.

## ٧) المتابعة والتحكّم

ما دام يعمل مخفياً، **`agent.log`** بهذا المجلد هو نافذتك عليه — يحتوي كل ما كانت
النافذة ستعرضه، ويُقصّ تلقائياً عند تجاوزه ١ ميغابايت.

| تريد | نفّذ |
|---|---|
| تعرف ماذا حدث | افتح **`agent.log`** |
| تشاهده مباشرة | شغّل `start-print-agent.bat` يدوياً |
| توقفه الآن | `Stop-ScheduledTask -TaskName "PizzaPrintAgent"` |
| تشغّله الآن | `Start-ScheduledTask -TaskName "PizzaPrintAgent"` |
| تلغيه نهائياً | `Unregister-ScheduledTask -TaskName "PizzaPrintAgent"` |

## ٨) ماذا يحدث عند الأعطال

| الحالة | ما يحدث |
|---|---|
| الجهاز مطفأ أو نائم | الفواتير تتراكم على الموقع وتُطبع **كلها** عند عودته |
| انقطاع الإنترنت | يعيد المحاولة بهدوء كل ٣٠ ثانية ويكتب في السجل عند عودة الاتصال |
| الطابعة مطفأة أو بلا ورق | الفاتورة تبقى بالطابور، ويعيد المحاولة بفواصل متزايدة (١٠ث ← ٣٠ث ← دقيقة ← ٥ دقائق) حتى تُحلّ |
| ظهور `the site rejected the token` | `token` هنا و`PRINT_AGENT_TOKEN` على الموقع غير متطابقين — أو لم يُعَد النشر بعد إضافته |
| لا تُطبع ولا تظهر أخطاء | تأكد أن الطابعة هي الافتراضية في Windows، أو اكتب اسمها في `config.json` |

الفاتورة لا تُعلَّم "مطبوعة" إلا بعد أن تقبلها الطابعة فعلاً — فلا شيء يضيع بصمت.

---

## ٩) إعادة الطباعة

زر **طباعة الوصل** في لوحة التحكم يعيد إدراج الفاتورة نفسها بالطابور، فتخرج خلال
ثوانٍ.

لم يعد يطبع لحظة الضغط، لأن الضغطة تحدث على الموقع بينما الورقة تخرج هنا. لذلك
الرسالة صارت **"أُرسل الوصل إلى الطابعة"** بدل "تمت الطباعة".

---

## ملاحظة عن عرض الورق

عرض الفاتورة (58 أو 80 ملم) يأتي **مع كل فاتورة** من إعدادات الموقع، ولا يُخزَّن
هنا. إذا غيّره الماستر من لوحة التحكم، تخرج الفاتورة التالية بالعرض الجديد
مباشرة — بلا تعديل على هذا الجهاز ولا إعادة تشغيل للوكيل.
